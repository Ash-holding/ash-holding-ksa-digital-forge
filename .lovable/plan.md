
## الهدف
إلغاء النوافذ المنبثقة (Sheets/Dialogs للتفاصيل) في لوحة الأدمن والعملاء واستبدالها بصفحات داخلية كاملة، مع مزامنة لحظية ثنائية الاتجاه بين الطرفين.

## نطاق العمل

### 1. صفحات تفاصيل داخلية جديدة (Admin)
لكل قسم: `list → /admin/<section>/:id` بدل الشيت.

| القسم | المسار الجديد | يحتوي |
|---|---|---|
| الفواتير | `admin.invoices.$id.tsx` | تفاصيل + بنود + دفعات مرتبطة + PDF + تحديث حالة + سجل نشاط |
| العقود | `admin.contracts.$id.tsx` | بنود + مرفقات + تجديد/إلغاء + توقيع |
| الخدمات | `admin.services.$id.tsx` | تعديل كامل + طلبات مرتبطة + إحصائيات |
| الدعم | `admin.support.$id.tsx` | محادثة كاملة + تعيين + أولوية + إغلاق (بدل Sheet) |
| المدفوعات | `admin.payments.$id.tsx` | تفاصيل + فاتورة/عقد مرتبط + إيصال |
| الملفات | `admin.files.$id.tsx` | معاينة + بيانات وصفية + مشاركة + سجل تحميل |
| المستخدمون | `admin.users.$id.tsx` | ملف كامل + الأدوار + الجلسات + IP |
| طلبات المشاريع | موجودة ✓ | — |

النماذج (إنشاء جديد) تبقى في `FormSheet` لأنها إدخال سريع، لكن التفاصيل والتعديل → صفحة داخلية.

### 2. صفحات تفاصيل داخلية (Client)
- `client.invoices.$id.tsx` — عرض + دفع + PDF
- `client.contracts.$id.tsx` — عرض + توقيع
- `client.support.$id.tsx` — محادثة تذكرة داخلية
- `client.payments.$id.tsx` — إيصال
- `client.services.$id.tsx` — تفاصيل الخدمة + طلب

### 3. المزامنة اللحظية
- توحيد `refetchInterval: 5000` + `refetchOnWindowFocus` لكل الاستعلامات في الأدمن والعميل.
- Hook مشترك `useLiveQuery` يفعّل التحديث اللحظي + `invalidate` عند أي `mutation` من الطرف الآخر.
- إشعارات WhatsApp تُطلق عند: تغيير حالة فاتورة/عقد/دفعة/تذكرة/ملف.
- شارة "مباشر" (`LiveBadge`) في رأس كل صفحة داخلية.

### 4. تصميم موحّد للصفحات الداخلية
هيكل ثابت:
```text
┌─ PageHeader (رجوع + عنوان + LiveBadge + أزرار سريعة)
├─ Hero Bento (بيانات رئيسية + حالة + مبالغ)
├─ Tabs: التفاصيل | النشاط | المرفقات | المحادثة
└─ Sidebar (Timeline + إجراءات الأدمن)
```
مع Framer Motion staggered + Skeleton loaders.

### 5. Backend
- إضافة `GET /:id` تفصيلي لكل مورد (invoices, contracts, services, payments, files, users, support/:id) يعيد بيانات مرتبطة.
- `PATCH /:id` شامل + إطلاق SmartWats.
- سجل تدقيق تلقائي لكل تعديل.

## التنفيذ على مراحل
سأنفذ على مرحلتين لتفادي الضخامة:
- **المرحلة 1 (هذه الرسالة):** الفواتير + العقود + الدعم + المدفوعات (الأكثر تفاعلاً) — أدمن + عميل + Backend + مزامنة لحظية.
- **المرحلة 2:** الخدمات + الملفات + المستخدمون + التقارير + الإعدادات + سجل التدقيق.

## ملاحظات تقنية (اختيارية)
- استخدام `queryClient.invalidateQueries` عبر `onSuccess` في كل mutation لضمان تحديث الطرف الآخر خلال ≤5s.
- الصفحات الداخلية تستخدم `Route.useParams()` بدل props.
- `LiveBadge` تظهر خضراء عند نجاح آخر polling، صفراء عند إعادة المحاولة.
- كل الحقول الحساسة (IP, الأدوار) تتحقق من `requireRole('ADMIN')` في الميدلوير.
