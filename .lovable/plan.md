# تطوير صفحات لوحة الأدمن بنمط عالمي موحد

الهدف: رفع صفحات (المشاريع، الخدمات، الفواتير، العقود، الدعم، المدفوعات، الملفات، المستخدمون، التقارير، الإعدادات، سجل التدقيق) لنفس مستوى صفحة العملاء — تصميم موحد، متجاوب، ولحظي.

## 1) طبقة مشتركة (Design System للأدمن)
إنشاء مكونات قابلة لإعادة الاستخدام في `src/components/admin/`:
- `AdminPageHeader` — عنوان + وصف + شريط أدوات (بحث، فلاتر، أزرار CTA) بتخطيط `grid-cols-[minmax(0,1fr)_auto]` للجوال.
- `AdminStatsRow` — صف MetricChip موحّد (نفس Bento) أعلى كل صفحة.
- `AdminDataTable` — جدول متجاوب: جدول على الديسكتوب، بطاقات مكدّسة على الجوال، Skeleton أثناء التحميل، فرز، بحث، صفحات، حالات فارغة.
- `AdminFilterBar` — شرائح فلترة (chips) موحّدة الشكل مع لون حالة.
- `StatusBadge` — بادجات دلالية موحّدة (مدفوع/معلّق/متأخر/مسودة…).
- `EmptyState` و `ErrorState` موحّدين.

## 2) التحديث اللحظي (Realtime)
- استخدام TanStack Query مع `refetchInterval: 15s` + `refetchOnWindowFocus` لكل قائمة إدارية.
- عند تفعيل Lovable Cloud مستقبلاً، بديل جاهز عبر Postgres Changes.
- Optimistic updates على الإجراءات (تحديث حالة فاتورة، إغلاق تذكرة دعم…).

## 3) الصفحات (يطبّق النمط نفسه على كل واحدة)

| الصفحة | Metrics أعلى | الأعمدة الرئيسية | إجراءات |
|---|---|---|---|
| المشاريع | إجمالي/نشط/متأخر/مكتمل | العميل، الحالة، الموعد، التقدم | إنشاء، تعديل، أرشفة |
| الخدمات | العدد/الأكثر طلبًا/الإيراد | الاسم، السعر، الحالة، الطلبات | إضافة/تعطيل |
| الفواتير | مستحق/مدفوع/متأخر | رقم، عميل، مبلغ، حالة، تاريخ | تسجيل دفع، PDF |
| العقود | ساري/منتهي/قيد التوقيع | عميل، مدة، قيمة، حالة | تجديد، إلغاء |
| الدعم | مفتوح/قيد المعالجة/مغلق/SLA | تذكرة، عميل، أولوية، مسند إليه | رد، إسناد، إغلاق |
| المدفوعات | إجمالي/اليوم/الشهر/فاشل | رقم، عميل، طريقة، حالة | استرجاع، تفاصيل |
| الملفات | العدد/السعة/الأنواع | اسم، مالك، حجم، تاريخ | معاينة، حذف |
| المستخدمون | إجمالي/نشط/معلّق/آخر 24س | اسم، بريد، دور، IP، آخر دخول | تفعيل/تعليق، تغيير دور |
| التقارير | KPIs + Charts | إيراد شهري، أكثر عميل/خدمة، معدل تحصيل | تصدير CSV |
| الإعدادات | تبويبات: الشركة، الفوترة، المظهر، الأمان، الإشعارات | — | حفظ |
| سجل التدقيق | إجمالي/اليوم/بحرِج | وقت، فاعل، فعل، مورد، IP | تصفية، تصدير |

## 4) صفحات فرعية داخلية (بدل المنبثقات)
لكل مورد: `admin.{res}.new.tsx` + `admin.{res}.$id.tsx` + `admin.{res}.$id.edit.tsx` عند اللزوم (نفس نمط العملاء).

## 5) الواجهة الخلفية (تدريجيًا حسب الحاجة)
- إبقاء الـ API الحالي، وإضافة endpoints مفقودة (payments/list, audit-log, reports/summary) مع Zod validation.
- ضخ بيانات تجريبية في `src/lib/demo-data.ts` لجميع الأقسام لعرض غني فوري.

## 6) التجاوب والاتساق
- شبكة Bento نفسها (نفس gaps 3/4، `min-w-0`, `truncate`, `shrink-0`).
- ألوان دلالية من `src/styles.css` فقط — لا ألوان مباشرة.
- RTL كامل، وأيقونات lucide موحّدة.

## خطة التنفيذ (مراحل)
1. **الأساس**: إنشاء المكونات المشتركة (AdminPageHeader/AdminDataTable/…).
2. **البيانات التجريبية**: إثراء demo-data لكل قسم.
3. **صفحات القوائم** (Batch 1): المشاريع، الخدمات، الفواتير، العقود.
4. **صفحات القوائم** (Batch 2): الدعم، المدفوعات، الملفات، المستخدمون.
5. **صفحات خاصة**: التقارير (رسوم)، الإعدادات (تبويبات)، سجل التدقيق (timeline + filters).
6. **الصفحات الفرعية** new/detail/edit للأقسام الرئيسية.
7. **Realtime polling + Skeletons + Empty/Error states**.

## أسئلة قبل البدء
- هل أنفّذ كل المراحل الآن دفعة واحدة (تغييرات كبيرة)، أم مرحلة-مرحلة مع مراجعتك بينها؟
- التقارير: أستخدم Recharts (مثبّت بالفعل) أم مكتبة أخرى؟
- الإعدادات: هل أبقيها Frontend-only الآن، أم أضيف حفظ فعلي بالـ backend؟
